# SmartShower: Rust-прошивка

Rust-версія прошивки на `esp-idf-svc` (std). Поведінка, Telegram-команди
і формат черги в NVS такі самі, як у C++-версії в корені репозиторію, тому
після перепрошивки черга не губиться.

```
firmware-rs/
  core/   # shower-core: логіка без заліза, тестується на ПК
  esp/    # прошивка: GPIO, TM1637, OLED, buzzer, Wi-Fi, NVS, бот
```

## Плати

Плату визначає таргет збірки, розкладка пінів лежить в `esp/src/board.rs`.

| Плата | Таргет | Команда |
|---|---|---|
| ESP32-WROOM | `xtensa-esp32-espidf` | `cargo build --release` |
| ESP32-C3 Super Mini | `riscv32imc-esp-espidf` | `cargo c3 build --release` |

**ESP32-WROOM:** піни як у C++-версії (таблиця в головному README).

**ESP32-C3 Super Mini:** має 13 GPIO, усі зайняті базовою периферією,
тому кнопки температури на цій платі не опитуються.

| GPIO | Призначення |
|---:|---|
| 0 / 1 | Кнопка душу 1 / 2 |
| 2 | TM1637 CLK (спільний) |
| 3 / 4 | TM1637 DIO душу 1 / 2 |
| 5 | Buzzer |
| 6 / 7 | Душ 1: червоний / зелений LED |
| 8 / 9 | OLED SDA / SCL |
| 10 | Кнопка черги |
| 20 / 21 | Душ 2: червоний / зелений LED |

Консоль на C3 йде через вбудований USB-Serial-JTAG.

## Підготовка

```fish
cargo install espup ldproxy --locked
espup install --targets esp32,esp32c3
```

Перед кожною збіркою в новому терміналі:

```fish
bass source ~/export-esp.sh   # fish (плагін bass); у bash: . ~/export-esp.sh
```

Перша збірка завантажує ESP-IDF v5.5.6 в `esp/.embuild/` і триває кілька
хвилин. Наступні збірки проходять швидко.

## Конфігурація

1. `cp esp/src/secrets.example.rs esp/src/secrets.rs`
2. Заповни Wi-Fi, токен бота, `ADMIN_ID` і `GROUP_ID`.
3. Розклад неробочого часу і таймзона задаються в `esp/src/config.rs`.

## Збірка, заливка, тести

```fish
cd firmware-rs/esp
cargo run --release        # зібрати, залити через espflash і відкрити монітор
cargo c3 run --release     # те саме для ESP32-C3

cd ../core
cargo test                 # логіка черги, розкладу, бота — на ПК
```

## Відмінності від C++-версії

- **Синхронізація потоків:** стан, спільний для бота і циклу заліза, лежить
  в `Arc<Shared>` з одним `Mutex`. Без нього компілятор не дасть звернутися
  до черги з іншого потоку.
- **Затримка бота:** long-poll Telegram триває 5 с замість 30, тому
  повідомлення «твоя черга наступна» надходить не пізніше ніж за кілька
  секунд. Друге TLS-з'єднання на C3 не вмістилося б у пам'ять.
- **Запис у флеш:** черга записується в NVS лише тоді, коли вона справді
  змінилась.
- **Кнопка душу в неробочий час:** у неробочий час натискання кнопки душу
  ігнорується і пізніше не спрацьовує.
- **OLED:** шрифт ISO-8859-5 з кирилицею. Літери «ґ» у ньому немає, на табло
  вона показується як «?».
