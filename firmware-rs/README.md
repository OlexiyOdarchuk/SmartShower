# SmartShower: Rust-прошивка

Прошивка для ESP32-WROOM на `esp-idf-svc` (std). Піни такі самі, як у
C++-версії (таблиця в головному README).

```
firmware-rs/
  core/   # shower-core: логіка без заліза, тестується на ПК
  esp/    # прошивка: GPIO, TM1637, OLED, buzzer, Wi-Fi, NVS, бот
```

## Як працює черга

- **Виклики.** Коли звільняється душ, система кличе стільки людей з
  початку черги, скільки кабінок вільно. Викликаний отримує в групі
  повідомлення з кнопками «✅ Йду» і «⏭ Пропустити вперед».
- **Хто зайшов.** Коли зачиняються двері, з черги знімається перший, хто
  натиснув «Йду». Якщо такого немає, знімається перший викликаний. Якщо
  нікого не кликали, у душі людина поза чергою, і черга не рухається.
- **Таймаут.** На підтвердження виклику дається 5 хв; після «Йду» ще 5 хв,
  щоб дійти. Хто не встиг, зсувається на одне місце нижче, а після 3
  пропущених викликів вибуває з черги.
- **Пропустити вперед.** Людина стає одразу за наступним, хто чекає. Це не
  штрафується.
- **Талони.** Фізична кнопка черги видає талон із номером (1–99) і
  показує його на OLED. Талон викликається табло і писком buzzer'а, а
  таймаути діють так само, як для всіх.
- **Очікування.** Бот рахує середню тривалість душу (зберігається в NVS)
  і з урахуванням того, скільки вже триває кожен зайнятий душ, оцінює
  очікування для кожної позиції.

## Розклад

Налаштовується в `esp/src/config.rs`.

| Режим | Коли | Що відбувається |
|---|---|---|
| Робочий | решта часу | черга рухається, виклики, таймаути |
| Перерва | 11:00–13:59 | черга заморожена, виклики скасовано, ставати в чергу можна |
| Ніч | 00:00–05:59 | на початку ночі черга очищається, ставати не можна, на OLED «OFF TIME» |

Поки час не синхронізувався з NTP, режим вважається робочим.

## Telegram

Бот тримає в групі одне закріплене повідомлення зі станом душів і черги.
Під ним кнопки «➕ Стати в чергу», «📍 Позиція» і «➖ Вийти». Відповідь на
натискання бачить лише той, хто натиснув, як спливаюче повідомлення, тож
група не засмічується. Щоб повідомлення закріпилось, бот має бути адміном з
правом закріплювати.

| Команда | Що робить |
|---|---|
| `/status` | Опублікувати статус заново (старий видаляється) |
| `/queue` | Стан черги відповіддю |
| `/position` | Твоя позиція й очікування |
| `/join_to_queue` / `/leave_from_queue` | Те саме, що кнопки |
| `/get_info` | Температура води в душах |
| `/clear_queue` | Очистити чергу (тільки `ADMIN_ID`) |

Бот працює у двох потоках на ядрі 0, у кожного своє TLS-з'єднання. Один
чекає оновлень (long-poll 25 с), другий одразу надсилає виклики, відповіді й
редагує статус. Цикл заліза працює на ядрі 1.

## Підготовка

```fish
cargo install espup ldproxy --locked
espup install --targets esp32
```

Перед кожною збіркою в новому терміналі:

```fish
bass source ~/export-esp.sh   # fish (плагін bass); у bash: . ~/export-esp.sh
```

Перша збірка завантажує ESP-IDF v5.5.6 в `esp/.embuild/` і триває кілька
хвилин.

## Конфігурація

1. `cp esp/src/secrets.example.rs esp/src/secrets.rs`
2. Заповни Wi-Fi, токен бота, `ADMIN_ID` і `GROUP_ID`.

## Збірка, заливка, тести

```fish
cd firmware-rs/esp
cargo run --release        # зібрати, залити через espflash і відкрити монітор

cd ../core
cargo test                 # логіка черги, розкладу, бота — на ПК
```

## Сумісність із C++-версією

Черга в NVS читається з формату C++-прошивки: анонімні записи з кнопки
отримують номери талонів. Після перепрошивки черга не губиться, але
виклики починаються заново.
